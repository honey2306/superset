ACP Markdown 样式优化方案对比

参考 Pi coding agent 的设计：所有标题用同一颜色，靠字号+字重区分层级 · 以下是 3 套优化方案

方案 1：克制主义
只有 h2 用主题粉色作为视觉锚点，其他标题全用灰度层级。类似 Linear / Notion 的做法，一个屏幕最多一处强调色。

主标题 H1：使用高对比灰色

这是正文段落，字号 15px，行高 1.7。用于长篇 CJK 阅读，保持舒适的呼吸感。通过合理的段落间距和行高，让文字有足够的空间呼吸。

次级标题 H2：唯一使用主题粉色

H2 是 Agent 输出中最常用的段落标题（占比 90%），因此给它主题色作为视觉锚点。这样一个屏幕里最多只有一处强调色，不会造成视觉疲劳。

三级标题 H3：高对比灰色

H3 使用 92% 不透明度的白色，比正文（88%）稍亮，但不用主题色。通过字号（16px）和字重（600）与正文区分。

四级标题 H4：中等灰色

H4 使用 75% 不透明度，明显比正文更灰，适合作为小节标题或补充说明。

文件路径和代码示例：src/components/Button.tsx 保持 sans 字体和淡背景，避免一行里满是 --flag 和 api.method() 时出现"粉色药丸"堆叠的视觉爆炸。

  • 列表项使用与正文相同的灰度
  • Marker 使用 45% 不透明度，足够低调
  • 保持 6px 的列表项间距，让内容透气
引用块使用 70% 不透明度和斜体，配合左侧边框，让引用内容明显区别于正文但不会过于突出。

加粗文字使用 98% 不透明度和 600 字重，斜体文字使用 92% 不透明度。链接使用青色（cyan）并带有淡淡的下划线。

方案 2：极简纯净
所有标题完全不用主题色，纯灰度层级。主题粉色只留给链接/tag/强调。inline code 切回 mono 字体。类似 GitHub / Stripe 文档。

主标题 H1：纯白高对比

这是正文段落，字号缩小到 14.5px，行高 1.65。更紧凑的排版适合对话流场景，一屏能看到更多内容。整体风格偏向技术文档的纯净感。

次级标题 H2：95% 白色

H2 也不用主题色，而是用 95% 不透明度的白色。标题层级完全靠字号、字重、灰度深浅来区分，没有任何彩色干扰。

三级标题 H3：88% 灰色

H3 使用 88% 不透明度，与正文（85%）有细微差别。字号 15.5px，比正文稍大，配合 600 字重形成层级。

四级标题 H4：72% 中灰

H4 使用 72% 不透明度，明显比正文更灰。适合作为小节标题或辅助性标题。

文件路径和代码示例：src/components/Button.tsx 切回等宽字体（mono），配合极淡背景（4% 不透明度）。这样路径和代码更有技术感，同时背景足够淡不会撑高行。

  • 列表项保持紧凑的行距
  • 整体节奏更快，适合快速浏览
  • 极简风格，没有任何彩色元素
引用块同样使用灰度，整个界面只有链接和语法高亮会出现颜色，其他全是黑白灰。

加粗文字和斜体文字也都是灰度，只有链接保留青色。这种极简风格让用户的注意力完全集中在内容本身。

方案 3：平衡优雅
H1 用淡雅粉色（75% 不透明度），其他标题用灰度。inline code 用 mono + 无背景 + 淡下划线。在品牌感和克制之间取得平衡。

主标题 H1：淡雅粉色

这是正文段落，字号 15px，行高 1.68。H1 使用主题粉色但降低到 75% 不透明度，让粉色变得更内敛、更优雅，不会过于抢眼。

次级标题 H2：95% 白色

H2 不用粉色，而是用高对比白色（95%）。这样 H1 的淡粉色就成为页面中唯一的品牌色点缀，既保留品牌识别度，又不会造成"粉色疲劳"。

三级标题 H3：88% 灰色

H3 使用 88% 不透明度的白色，与正文（87%）略有差异。字号 16px，配合 600 字重，形成清晰的层级。

四级标题 H4：70% 中灰

H4 使用 70% 不透明度，明显比正文更灰，适合作为补充性标题。

文件路径和代码示例：src/components/Button.tsx 使用 mono 字体，但去掉背景，改用淡淡的下划线（12% 不透明度）。这样既有技术感，又不会因为背景块让行高变得参差不齐。

  • 列表项保持适中的间距
  • 行高 1.68 让 CJK 文字有足够呼吸空间
  • 整体风格在克制和品牌感之间取得平衡
引用块使用灰度和斜体，配合左侧边框。整体排版在专业感和亲和力之间找到平衡点。

加粗文字使用高对比白色，斜体文字稍弱一些。链接保留青色和下划线。这个方案结合了方案 1 和方案 2 的优点。

方案 4：Pi 排版哲学 + Superset 主题色（完整映射）
所有元素都对齐 Pi：正文/标题/code/链接/列表/引用/hr。Pi 原色映射到 Superset 主题色（金→粉、青→粉、蓝→cyan、accent→灰）。

主标题 H1：粉色 17px 700

正文 14.5px、行高 1.72、段间距 10px、色 rgba(255,255,255,0.86)。字号收敛让排版紧凑，行高稍大保持透气。

次级标题 H2：粉色 15.5px 600

标题字号跨度极小（17→15.5→14.5），靠字重和粉色识别"这是标题"，不再靠字号大小分层级。标题下距 4-8px，紧贴段落。

三级标题 H3：粉色 14.5px 600

H3 与正文同字号，仅字重不同。深层级用得少，不需要再细分。

四级标题 H4：粉色 14.5px 600

inline code 完全无背景：src/components/Button.tsx、useMediaQuery()、--flag、process.env.NODE_ENV。一段话满是 code 也不会撑高行、堆叠药丸。mono 字体 + 主题粉 + 0.88em。

链接用 Superset cyan：Read the docs、GitHub Issue #123、https://superset.ai/api。下划线用同色 30% 透明度，hover 时加深。

文件路径：路径就是 inline code，不做特殊区分。apps/desktop/src/renderer/screens/main/AcpSessionPane.tsx 和 packages/db/src/schema/user.ts 都是 mono + 粉色 + 无背景。

无序列表：marker 用 35% 白色纯灰（Pi 原本用 accent 色，映射时避免粉色堆叠）：

  • 列表项字号继承正文 14.5px
  • 行高 1.72，marker 纯灰不抢戏
  • 项间距 4px，紧凑但不粘连

有序列表：数字 marker 用 50% 白色纯灰：

  1. 第一步：读取 package.json
  2. 第二步：调用 bun install
  3. 第三步：验证 安装结果
引用块用纯灰 + 不用斜体（Pi 保持中性）。左边框 2px、15% 白色，文字 60% 白色。适合放长引用不会太扎眼。

加粗用 98% 白色 + 600 字重、斜体用 90% 白色。粗+code+斜组合起来也不打架。

分隔线用 8% 白色，极淡。整个系统只有 3 种颜色：正文白、粉色（标题+code）、青色（链接）。

方案 5：严格 Pi 规矩（一色一语义）
严格遵守 Pi 的核心原则：一个颜色只表达一个语义。粉色=标题、cyan=代码、紫=链接、其他=灰。视觉信号极其干净，各司其职。

主标题 H1：只有粉色标题会出现

正文 14.5px、行高 1.72，色 rgba(255,255,255,0.86)。排版节奏完全按 Pi。

次级标题 H2：粉色只做标题信号

粉色在整个文档中只表示"这是标题"，不会出现在正文/代码/链接里。你眼睛看到粉色，立刻知道那是一个标题。

三级标题 H3

字号收敛、字重区分（600/700），层级依然清晰。

四级标题 H4

inline code 用 cyan（对应 Pi 的 accent 青）：src/components/Button.tsx、useMediaQuery()、--flag、process.env.NODE_ENV。cyan 在整个文档中只标记代码。

链接用 柔和紫（避开 cyan 撞色）：Read the docs、GitHub Issue #123、https://superset.ai/api。紫色在整个文档中只标记链接。

文件路径：路径就是 inline code，全部用 cyan。apps/desktop/src/renderer/screens/main/AcpSessionPane.tsx、packages/db/src/schema/user.ts。

无序列表：marker 用纯灰，避免占用颜色语义：

  • 列表项字号继承正文 14.5px
  • marker 35% 白色纯灰
  • 项间距 4px，紧凑但透气

有序列表：

  1. 读取 package.json
  2. 调用 bun install
  3. 验证 安装结果
引用块纯灰、不用斜体。左边框 2px 15% 白，文字 60% 白。放长引用不扎眼。

加粗用 98% 白色（不加色相）、斜体用 90% 白色。粗+code+斜组合，每个信号各自独立。

整个系统 3+1 种颜色，各司其职：

  • 正文白 - 内容主体
  • 粉色 - 只标题
  • cyan - 只代码
  • 紫色 - 只链接

看到任何一种颜色，语义都是唯一的。这就是 Pi 一色一语义的核心。
