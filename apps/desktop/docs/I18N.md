# Desktop internationalization

The desktop renderer supports `en-US` and `zh-CN`. The selected locale is
persisted locally under `superset.desktop.locale`; Chinese is selected by
default when the operating system prefers a Chinese locale.

## Rendering localized UI text

Use the renderer translation hook in a React component:

```tsx
import { useTranslation } from "renderer/providers/I18nProvider";

export function Example() {
	const { t } = useTranslation();
	return <Button>{t("navigation.settings")}</Button>;
}
```

Add each key to both `enUSMessages` and `zhCNMessages` in
`src/renderer/providers/I18nProvider/messages.ts`. The catalog test ensures
that the two language catalogs stay in sync.

## Message values

Messages support named values:

```tsx
t("git.worktreeLocationHint", { host: hostName });
```

Use descriptive names rather than positional values so translators can reorder
the sentence naturally.

## Migration rules

- New user-visible renderer strings must use `t()`.
- Keep stable message keys in English and group them by feature.
- Do not localize source code, terminal output, file paths, user content, or
  third-party service payloads.
- Use `Intl` with the active locale for dates, numbers, and relative time.
- Main-process menus, notifications, and native dialogs must use the same
  catalog before a locale is declared fully supported.
